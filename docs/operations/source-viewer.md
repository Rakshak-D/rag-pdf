# Opening PDF sources

Documents offers a **Preview** action for each imported PDF. The viewer reads the original bytes from the authenticated local bootstrap API and checks the current source manifest and document digest before returning them. A source that has changed since the list or citation was created must be refreshed and reopened; the viewer never substitutes another PDF.

Document Chat citations can open the matching source at the returned page. The Ask response supplies document identity, manifest identity, page and passage text; it does not supply trusted PDF rectangles. The viewer uses the actual PDF.js text layer and viewport to locate the passage, then validates identity, page, text continuity and complete rendered geometry before drawing a highlight. If a text match is missing, ambiguous or geometrically incomplete, the viewer shows `Passage on page N` and draws no source highlight. Figure citations without locatable caption text use `Figure on page N`. A restored answer whose evidence has expired cannot open its old source link.

The viewer accepts complete PDFs up to 16 MiB and 200 pages, subject to the bootstrap request-size setting, which may set a lower limit. This also means a PDF imported under an earlier, higher setting may no longer fit the current viewer limit. The viewer does not request HTTP ranges or persist document bytes. The gateway permits PDF content only on the exact authenticated source route; browser code receives no backend credential. PDF.js scripting, XFA, WebAssembly, range fetching and annotation actions are disabled. If the source changes, disappears, exceeds the limit or cannot be rendered, the viewer reports the failure and provides a return path.
